Users

The name is the sub of every token issued to that person. Passwords and claims are stored as typed, in . This is a test system and nothing about it is safe.

Add a user, or change one

A blank password keeps an existing user's. The claims are the standard ones of OpenID Connect Core 5.1, released only for the scope that asks for them - profile, email, address, phone. Blank keeps a user's claims; {} removes them.

Clients

The three checks a real OpenID Provider makes and this service did not: an unknown client_id is refused, a redirect_uri that is not registered for the client is refused, and a client_secret is checked. While this list is empty none of them happen — which is how a deployment adopts the registry without a flag day, and also why a component can work here and fail against Keycloak until it is filled in.

Register a client, or replace one

A blank secret makes it a PUBLIC client, which must then authenticate with none. Registering the first client turns the checks on for every client.

Mint a token

This posts to /mint, the same endpoint a script calls, so what can be asked for here is exactly what can be asked for there — including tokens a participant must refuse.
